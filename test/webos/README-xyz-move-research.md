# CAD feature-gap and XYZ move research

Research based on unified source `7242e2d6`, compared with upstream `dev` `ca3e2b19`, the `surfacing-refactor` reference and closed PR #218 `b86c3917`. No engine is replaced and this is not a production deployment.

The unified branch already includes datum-based `MOVE_BODY`, Get Info, sketch DXF import and a separate surfacing workspace. It lacks direct XYZ move, axis-angle rotate, the PR's split body, interactive point-to-point measurement and its NavCube. Upstream dev also has `SIMPLIFY` and `DRAFT_FACES` operations absent here, plus more extensive sketch-placed hole logic. The existing unified hole operation creates and returns tool geometry, rather than consuming a target body for an automatic cut. Surfacing's independent native boolean service is not the same as a complete, selectable backend for every existing modeling operation.

These are not drop-in ports. PR #218's move/rotate omit stable topology identities; its split scans at most 20 results and selects a shell even though the description mentions a face or plane. Its measurement interaction is primarily mouse events. Upstream `SIMPLIFY` invokes `fixshape`, unavailable in the existing 5efaf53 OCC engine (an unknown command trapped that engine during independent testing); draft and hole workflows require separate shape/reference and engine tests. Camera and mobile changes also require lifecycle, CSP and input review. This is a bounded review, not an exhaustive feature list.

`MOVE_BODY_XYZ` adapts the idea from PR #218 (author Pesicp). It provides direct X/Y/Z distances on one or more BREP bodies, validates finite values and inputs before copying, checks OCC command return codes, and assigns deterministic copied topology IDs. It retains existing datum-based Move Body. The face mapping uses the current same-topology analyzer's OCCT iteration order; geometric identity across arbitrary complex solids or engine versions remains unproven.

Run `test/webos/move-xyz-browser.test.cjs` against a built app and test helper at `JSKETCHER_TEST_URL`, with Puppeteer Core and a Chromium debugging endpoint at `CODI_TEST_CDP`. The scripted wizard moves a box, verifies actual translated face vertices and IDs, traverses undo/redo, saves/restores, then creates and restores a linear pattern referencing a moved face. It does not test touch, multiple selected bodies, all shape kinds, or a real host account.

`test/webos/geometry-engine-comparison-browser.test.cjs` requires the CSP-safe Manifold rebuild and `static/surfacingTest.bundle.js` built from `surfacing-webpack.config.cjs`. Under a served strict CSP including `wasm-unsafe-eval` but excluding JavaScript `unsafe-eval`, it checks six bounded same-box OCC/native cases. It documents a thin-overlap numerical difference due to different precision/tolerances; it is not proof of general equivalence. The shipped npm Manifold 3.4.1 does not pass this CSP without the separate source-rebuild integration.

The base `7242e2d6` has four existing `FaceRef` TypeScript mismatches in extrude/loft/revolve/sheet-metal. Later classifier work addresses them. The move addition introduces no new type-check errors on that base; this research branch should be integrated with that later fix rather than declared type-clean on its own.

Full-tree lint on base `7242e2d6` reports five pre-existing surfacing/mesh errors and 34 warnings; the new move source and touched workbench index have no reported lint problems. The final integration needs the separate surfacing lint/type cleanup already in progress.
